# 0003. Поиск пути

Статус: предложено
Дата: 2026-10-14
Требования: FR-HERO-01, FR-NPC-07, FR-WAR-06, NFR-02, NFR-04; §17 GDD (A* + HPA* + кэш регионов); риск «производительность поиска пути» из §19

## Контекст

Сетка 512² в MVP и 1024² позже, 100 жителей и 300 существ, весь тик ≤ 8 мс. Тайлы часто меняются: стены, двери, вырубка. Обрывы высотой ≥ 2 непроходимы. Враги при набеге должны выбирать путь с учётом стоимости пролома стен. Симуляция детерминирована. Подробности и источники: `docs/research/pathfinding.md`.

Ключевые выводы исследования:
- RimWorld обходится обычным A* на сетке с целочисленными стоимостями и лимитом узлов. Вопрос «достижимо ли» решается отдельно, через регионы и компоненты связности.
- HPA* даёт до 10 раз быстрее на длинных путях, но при каждой правке стены пересчитывает рёбра кластера. Для часто меняющейся карты колонии это дорого.
- Factorio использует абстракцию по чанкам как эвристику для A*, а не как замену.
- Flow fields выгодны для сотен агентов к одной цели. Это армии v1, а не отряды до 12 бойцов.
- Готовые C#-библиотеки не заявляют детерминизм и работу без аллокаций.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Только A* | Просто | Поиск к недостижимой цели обходит всю карту |
| A* + карта связности (регионы) | «Достижимо?» за O(1); дешёвые инкрементальные обновления | Две структуры вместо одной |
| HPA* с самого начала, как в GDD | Быстрые длинные пути | Дорогие обновления при стройке; сложнее; в MVP нет путей через всю карту |
| Flow fields | Дёшево для толп | Нужен кэш полей; для одиночных агентов неэффективно |

## Решение

**MVP (M2–M5):**
- A* на 8-связной сетке. Стоимости целые: 10 по прямой, 14 по диагонали. Срезать угол у стены нельзя.
- Двоичная куча с детерминированным ключом сравнения: f, затем h, затем индекс тайла. Массивы узлов переиспользуются через счётчик поколений, без аллокаций на запрос.
- Лимит узлов на один запрос; при превышении возвращается частичный путь к лучшему узлу.
- **Карта связности** по регионам до 16×16 внутри чанка. Регион перестраивается только при изменении его тайлов. Запрос «достижимо ли» проверяется до A* и отсекает безнадёжные поиски.
- Два слоя связности: обычный и «с проломом», где разрушаемые постройки считаются проходимыми.
- Для врагов, которые умеют ломать, стоимость тайла с постройкой = время пролома в тиках по формуле из `gdd-issues` G4. Коэффициенты в `data/balance.json`.
- **Очередь запросов** с бюджетом узлов на тик. Порядок обработки детерминирован: приоритет, затем ID сущности, затем номер запроса. Агент перепланирует не чаще раза в 10 тиков, если путь не стал недействительным.
- Всё в однопоточном коде Core.

**v1 и позже:**
- Абстрактный граф по чанкам или регионам как эвристика для длинных путей на 1024² и 2048², по образцу Factorio. Это и есть «иерархический» поиск из GDD, но без дорогих обновлений HPA*.
- Flow fields для армий фракций.
- Кэш путей с частичным переиспользованием.

## Последствия

- Отклонение от буквы §17 (HPA* в MVP) не меняет требований: это выбор реализации, а не функциональности. Перевод HPA* на v1 отражён здесь, правка GDD не нужна.
- Пишем свою реализацию: оценка 300–500 строк на A* и 400 строк на карту связности. Плюс бенчмарк-тест с M2: 100 агентов, случайные пути на 512².
- Детерминизм проверяется тестом-реплеем: одинаковые пути при одинаковом seed и командах.
