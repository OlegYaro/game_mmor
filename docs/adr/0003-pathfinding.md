# 0003. Поиск пути

Статус: принято
Дата: 2026-10-14
Требования: FR-HERO-01, FR-NPC-07, FR-WAR-06, NFR-02, NFR-04; §17 GDD (A* + HPA* + кэш регионов); риск «производительность поиска пути» из §19

## Контекст

Сетка 512² в MVP и 1024² позже, 100 жителей и 300 существ, весь тик ≤ 8 мс. Тайлы часто меняются: стены, двери, вырубка. Обрывы высотой ≥ 2 непроходимы. Враги при набеге должны выбирать путь с учётом стоимости пролома стен. Симуляция детерминирована. Подробности и источники: `docs/research/pathfinding.md`.

Ключевые выводы исследования:
- RimWorld обходится обычным A* на сетке с целочисленными стоимостями и лимитом узлов. Вопрос «достижимо ли» решается отдельно, через регионы и компоненты связности.
- HPA* даёт до 10 раз быстрее на длинных путях, но при каждой правке стены пересчитывает рёбра кластера. Для часто меняющейся карты колонии это дорого.
- Factorio использует абстракцию по чанкам как эвристику для A*, а не как замену.
- Flow fields выгодны для сотен агентов к одной цели. Это армии v1, а не отряды до 12 бойцов.
- Готовые C#-библиотеки не заявляют детерминизм и работу без аллокаций.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Только A* | Просто | Поиск к недостижимой цели обходит всю карту |
| A* + карта связности (регионы) | «Достижимо?» за O(1); дешёвые инкрементальные обновления | Две структуры вместо одной |
| HPA* с самого начала, как в GDD | Быстрые длинные пути | Дорогие обновления при стройке; сложнее; в MVP нет путей через всю карту |
| Flow fields | Дёшево для толп | Нужен кэш полей; для одиночных агентов неэффективно |

## Решение

**MVP (M2–M5):**
- A* на 8-связной сетке. Стоимости целые: 10 по прямой, 14 по диагонали. Срезать угол у стены нельзя.
- Двоичная куча с детерминированным ключом сравнения: f, затем h, затем индекс тайла. Массивы узлов переиспользуются через счётчик поколений, без аллокаций на запрос.
- Лимит узлов на один запрос; при превышении возвращается частичный путь к лучшему узлу.
- **Карта связности** по регионам до 16×16 внутри чанка. Регион перестраивается только при изменении его тайлов. Запрос «достижимо ли» проверяется до A* и отсекает безнадёжные поиски.
- Два слоя связности: обычный и «с проломом», где разрушаемые постройки считаются проходимыми.
- Для врагов, которые умеют ломать, стоимость тайла с постройкой = время пролома в тиках по формуле из `gdd-issues` G4. Коэффициенты в `data/balance.json`.
- **Очередь запросов** с бюджетом узлов на тик. Порядок обработки детерминирован: приоритет, затем ID сущности, затем номер запроса. Агент перепланирует не чаще раза в 10 тиков, если путь не стал недействительным.
- Всё в однопоточном коде Core.

**v1 и позже:**
- Абстрактный граф по чанкам или регионам как эвристика для длинных путей на 1024² и 2048², по образцу Factorio. Это и есть «иерархический» поиск из GDD, но без дорогих обновлений HPA*.
- Flow fields для армий фракций.
- Кэш путей с частичным переиспользованием.

## Последствия

- Отклонение от буквы §17 (HPA* в MVP) не меняет требований: это выбор реализации, а не функциональности. Перевод HPA* на v1 отражён здесь, правка GDD не нужна.
- Пишем свою реализацию: оценка 300–500 строк на A* и 400 строк на карту связности. Плюс бенчмарк-тест с M2: 100 агентов, случайные пути на 512².
- Детерминизм проверяется тестом-реплеем: одинаковые пути при одинаковом seed и командах.

## Уточнения 15.10.2026 (пересмотр дизайна, `docs/MVP.md`)

- Осада на той же карте (P-19) добавляет в граф пути два вида связей: **стена — поверхность, по которой ходят** (отдельный слой проходимости по верху стены, вход через лестницу или башню) и **лестница — временная связь** между землёй и верхом стены, которая появляется при штурме и исчезает, когда её сбросили. Структура должна допускать временные рёбра в карте связности без перестройки региона: решение по ней — исследование #7, пока не принято.
- Ворота — проходимые для своих и разрушаемые для врагов; в слое «с проломом» (G4) стоимость пролома берётся из прочности ворот и стены.
- Дороги (P-16) меняют стоимость тайла: по дороге ходят быстрее. Стоимость пути по дороге и по тропе — в `data/balance/` (исследование #2). Тайлы тропинок меняют только стоимость, не связность, поэтому регионы из-за них не перестраиваются.
- Размер мира 2048² (P-07) закладывает на v1 абстрактный граф по чанкам; в MVP остаётся A* и карта связности.
- Перемещение героя через карту мира (P-20) путь по тайлам не ищет: длина пути считается на абстрактном графе чанков (исследование #9).
- Статус не меняется: решение «A* и карта связности» остаётся принятым.

## Реализация M2 (15.10.2026)

Код: `src/Core/Pathfinding/`, тесты: `tests/Core.Tests/Pathfinding/`.

- `PassabilityGrid` — единственное место правил движения: вода, озёра, океан и реки непроходимы, перепад высот ≥ 2 между соседями непроходим в обе стороны (B2), диагональ разрешена только если разрешены оба обхода через боковые тайлы и сама диагональ не пересекает обрыв. Статическая часть правил считается один раз в байт разрешённых направлений на тайл; оверлей `ITileBlocker` (по умолчанию `NoTileBlocker`) только снимает биты. Стоимость тайла — `ITileCost` в целых (по умолчанию 10 по прямой, диагональ = стоимость × 14 / 10).
- A*: индексированная двоичная куча (decrease-key) с ключом (f, h, индекс тайла), записи узлов по 8 байт на тайл с поколениями на отрезки по 32 записи, без аллокаций после прогрева. Эвристика — октильная с минимальной стоимостью шага, поэтому остаётся допустимой при дорогах дешевле 10. При исчерпании лимита узлов — частичный путь к закрытому узлу с наименьшим h.
- `ConnectivityMap`: регионы в клетках 16×16 (четыре на чанк 32×32), связи регионов через границы клеток, компоненты — union-find по графу регионов. `Invalidate(x, y)` помечает клетку, перестройка ленивая (при следующем запросе) и касается только грязных клеток плюс один проход union-find. Первое построение полное, но отложено до первого запроса: глобальная связность не строится по частям без потери ответа за O(1).
- `PathRequestScheduler` (имя «Queue» запрещено анализатором CA1711): порядок (приоритет по убыванию, ID сущности, номер запроса), одна ожидающая заявка на сущность, интервал перепланирования и бюджет узлов на тик из `PathfinderConfig`. Поиск не прерывается бюджетом, поэтому тик может превысить бюджет не больше чем на один запрос.
- `Pathfinder.FindPathToAdjacent` / `TryFindApproachTile` — подход к непроходимой цели (дерево, здание): ближайший по стоимости из восьми соседей.

Замеры (Release, macOS, `PathfindingBenchmarkTests`): около 65 нс на узел; 100 агентов на 512² — средний тик 1,3–2,8 мс, максимум 3,9 мс при бюджете 40 000 узлов; путь через карту 2048² — 0,6–1 млн узлов, 50–85 мс; построение связности 2048² — 20–50 мс, 5,2 МиБ, обновление одного тайла около 0,1 мс; массивы A* на 2048² — 32 МиБ.

Герой (M2, волна 2): приказы ищут путь синхронно (`Pathfinder.FindPath` / `FindPathToAdjacent` с лимитом `PathfinderConfig.MaxNodesPerRequest`), путь целиком лежит в компоненте `Mover` и входит в хэш и сохранение, поэтому очередь запросов для героя не нужна. На конце частичного пути и перед шагом в ставший непроходимым тайл путь планируется заново. Блокировщик игры — слой занятости `TileChanges` (ADR 0007), он сам вызывает `NotifyTileChanged`. Шаг стоит `stepTicks` тиков по прямой и `stepTicks × 1,4` по диагонали (то же отношение 14/10, что в стоимости пути).

Уточнение 16.10.2026 (застревание частичного поиска): поиск с лимитом заканчивается на узле с наименьшей эвристикой, чаще всего у обрыва или берега рядом с целью, и новый поиск оттуда снова упирается в лимит и возвращает только сам старт. Раньше приказ отклонялся как «недостижимо» или герой вставал с `PathBlocked`, хотя карта связности говорит «достижима» (около 2% достижимых пар до 40 тайлов на 2048²). Теперь `HeroRules.FindPath` при частичном пути длины 1 один раз повторяет поиск с лимитом во всю карту (`min(число тайлов, MaxNodeLimit)`). Частичный результат возвращается только после проверки связности, так что цель заведомо достижима. Эвристика конца частичного пути строго убывает от поиска к поиску, поэтому герой не зацикливается. Правило одно для приказов движения и сбора и для перепланирования в пути. Замеры повторного поиска (Release, 1024² и 2048²): медиана 35–55 тыс. узлов, 3–5 мс; максимум в выборке около 300 тыс. узлов, до 40 мс; обход через всю карту 2048² — до 50–90 мс. Это разовый всплеск на приказ героя, а не постоянная нагрузка тика. Для жителей (M3) тот же приём через очередь запросов не подойдёт; там нужна эвристика по абстрактному графу (v1) или поиск, который продолжается в следующем тике.

Пока не сделано: слой связности «с проломом» (M4, второй экземпляр `ConnectivityMap` над сеткой с другим блокировщиком), стоимость пролома, временные рёбра лестниц, сохранение очереди запросов.
