# 0008. Контент в JSON и схемы

Статус: предложено
Дата: 2026-10-14
Требования: FR-MOD-01, FR-MOB-01, FR-ECO-02, FR-EXP-01, FR-UI-09; задел под FR-MOD-02

## Контекст

Весь контент и баланс лежит в `data/*.json` со схемами. Магические числа баланса в коде запрещены. Нужны валидация при загрузке, горячая перезагрузка в разработке и задел под моды. Подробности и источники: `docs/research/json-content.md`.

Ключевые факты:
- JsonSchema.Net 9.4.1 поддерживает draft 2020-12 и .NET 8–10, лицензия MIT. С версии 9.0 автор ввёл «Open Source Maintenance Fee», условия которого надо проверить до коммерческого релиза.
- В System.Text.Json есть строгий режим: запрет неизвестных полей с .NET 8, обязательные параметры конструктора с .NET 9, готовый пресет `Strict` в .NET 10.
- `JsonSchemaExporter` генерирует JSON Schema из C#-типов с .NET 9.
- Схема не умеет проверять ссылки между файлами, это нужно делать отдельным проходом.

## Варианты

| Валидация | Плюсы | Минусы |
| --- | --- | --- |
| JsonSchema.Net 9.4.1 | Draft 2020-12; MIT; .NET 8–10; схемы компилируются один раз | С 9.0 условия maintenance fee; проверить до коммерческого релиза |
| Corvus.JsonSchema | Apache-2.0; быстрый | Сильная сторона — генерация типов из схемы, нам не нужна; V5 требует .NET 9+ |
| NJsonSchema | Популярен | Тянет Newtonsoft.Json; поддержка 2020-12 не подтверждена |
| Только строгий разбор System.Text.Json и свои проверки | Ноль зависимостей | Нет проверки самих схем; ограничения дублируются в коде |

| Схемы | Плюсы | Минусы |
| --- | --- | --- |
| Рукописные JSON Schema | Полный контроль | Расходятся с C#-типами при правках |
| Генерация из C#-типов через `JsonSchemaExporter` | Один источник правды; CI ловит расхождение | Ограничения нужно выражать атрибутами |

## Решение

- **Типы контента** — `record` в Core, разбор через System.Text.Json с source generator и строгими опциями. Числа баланса — `int`.
- **Схемы генерируются из C#-типов** утилитой в `tools/` через `JsonSchemaExporter` и лежат в `data/schema/`. CI проверяет, что сгенерированные схемы совпадают с закоммиченными. Ограничения диапазонов задаются атрибутами на типах.
- **Валидация по схеме** через JsonSchema.Net — в тестах, в CI и в отладочной сборке при горячей перезагрузке. В релизную сборку пакет не входит: там работают строгий разбор и проверки каталога. Так условия maintenance fee затрагивают только разработку, а не распространяемую игру. Решение пересматривается перед модами (v2), где нужна валидация у игрока.
- **Организация:** файлы по категориям (`data/creatures/`, `data/buildings/`, `data/items/` и т. д.), в каждом массив объектов и ссылка `$schema`. ID в `snake_case`, с необязательным префиксом мода `modid:`.
- **Каталог** неизменяемый. Симуляция хранит числовой `DefId`, а не ссылки на объекты. Проверка ссылок между определениями идёт отдельным проходом после загрузки всех категорий. Все ошибки собираются в один список.
- **Горячая перезагрузка** только в разработке: наблюдение за файлами с задержкой около 200 мс, полная пересборка каталога, подмена на границе тика. Если ID удалён, подмена отклоняется с ошибкой в консоли.
- **Моды (v2):** сейчас закладываем только слои каталогов и JSON Merge Patch по RFC 7386 поверх объекта с тем же ID.
- **Локализация:** Core хранит только ключи, выведенные из ID (`creature.orc_warrior.name`). Переводы ru и en лежат в `locale/*.csv` для `TranslationServer` Godot. Тест проверяет, что у каждого ключа есть оба перевода.

## Последствия

- Добавление существа или здания не требует кода (FR-MOB-01), если его поведение собрано из существующих.
- Риск: условия maintenance fee у JsonSchema.Net. Запасные варианты — Corvus.JsonSchema (Apache-2.0) или только строгий разбор и проверки каталога.
