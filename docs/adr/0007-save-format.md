# 0007. Формат сохранений и миграции

Статус: принято
Дата: 2026-10-14
Требования: FR-SAVE-01, 02, 03, 04; FR-WORLD-05

## Контекст

Сохранение = seed + разница тайлов с исходной генерацией + полное состояние симуляции. Версия формата в каждом файле, миграции между версиями. Тест «сохранить, загрузить, сохранить» даёт побайтово идентичный файл. Цель v1: мир 1024² с 50 жителями за ≤ 2 с и ≤ 20 МБ. Подробности и источники: `docs/research/save-format.md`.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| System.Text.Json + source generator + Brotli | Миграции на уровне JSON-дерева; читается при отладке; встроен в .NET | Больше байт и медленнее бинарных форматов |
| MessagePack-CSharp | Быстрее и компактнее; MIT | Миграции сложнее; в 2026 были CVE, нужна версия ≥ 3.1.7 |
| MemoryPack | Самый быстрый | Не самоописывающий, миграции только добавлением полей |
| Свой BinaryWriter | Полный контроль | Свой фреймворк версий и миграций |

## Решение

- **Контейнер:** первая строка — несжатый JSON-заголовок `{formatVersion, gameVersion, worldGenVersion, seed, codec}`. Дальше тело в Brotli.
- **Тело:** System.Text.Json с source generator. Опции канонические: без отступов, все поля пишутся всегда, порядок свойств фиксирован, словари отсортированы, NaN и бесконечности запрещены.
- **Слой DTO** отделён от состояния симуляции. DTO описывают только текущую версию формата.
- **Миграции:** линейная цепочка `v1 → v2 → …` на уровне `JsonNode` до разбора в DTO. Каждая миграция покрыта файлом-образцом старой версии в тестах.
- **Разница тайлов:** по чанкам 32×32. На чанк хранится битовая маска изменённых тайлов (128 байт) и плотный массив изменённых значений. Оценка для 1024² при 10% изменений: около 0,55 МБ до сжатия.
- **Запись атомарная:** во временный файл, сброс на диск, переименование поверх старого.
- **Слоты и автосохранения:** ручные слоты и ротация трёх последних автосохранений по FR-SAVE-01. Путь к папке Core получает параметром. Godot передаёт `user://`.
- **Тесты:**
  - побайтовая идентичность после круга save → load → save;
  - образцы всех прошлых версий загружаются;
  - рефлексивный страж: каждое поле состояния либо сериализуется, либо помечено как исключённое с причиной;
  - хэш состояния до и после загрузки совпадает (ADR 0005).
- **Запасной путь при нехватке скорости:** MessagePack-CSharp ≥ 3.1.7 с тем же слоем DTO.

## Последствия

- Отладка сохранений возможна без спецтулов: заголовок читается глазами, тело распаковывается стандартными средствами. Есть флаг разработчика для записи с отступами.
- Канонический формат упрощает и тест идентичности, и хэш состояния.

## Уточнения M0

- Кодек назван `json-brotli` (имя без плюса).
- Dev-режим с отступами пишет несжатое тело с кодеком `json`.
- Replay-файл содержит поле `endTick`.
- Тело без контрольной суммы: порчу обнаруживают через распаковку Brotli и разбор JSON.

## Уточнения M1

- Формат v2 (`SaveFormat.CurrentVersion = 2`). В теле добавлены `game` (`difficulty`: `peaceful`/`normal`/`hard`, `mapSize`, `mapHash`), `fog` (`exploredRuns`) и хранилище компонентов `components.revealer`. Заголовок не менялся.
- Карта в сохранение не пишется. При загрузке она генерируется заново из `seed`, `mapSize` и `worldGenVersion` заголовка, её хэш сверяется с `mapHash`. Расхождение даёт ошибку `WorldGenMismatch`: генератор или `data/worldgen` поменялись без повышения версии генератора.
- Туман: сохраняется только слой «разведано», длинами серий по тайлам в порядке `y * size + x` (начиная с серии неразведанных, нулевой может быть только первая). Слой «видно сейчас» вычисляется заново после загрузки. Карта 512² после `reveal` весит в сохранении `[0, 262144]`.
- Миграция v1 → v2 (`SaveMigrationV1ToV2`): старые сохранения становятся симуляцией без мира: `mapSize = 0`, `mapHash = 0`, сложность `normal`, пустые `exploredRuns` и `revealer`. Образец `save_v1.sav` загружается через неё; добавлен образец `save_v2.sav` с миром 64².
- Replay-файл (формат 1) получил необязательные поля `mapSize` и `difficulty`. Они пишутся только для игры с миром, поэтому старые эталоны изменились лишь в строке `contentHash`.

## Уточнения 15.10.2026 (пересмотр дизайна): формат v3

План, код — в фазе 3 и позже. Новые данные в сохранении (формат v3, миграция v2 → v3 по ADR выше):

- **Тропинки и дороги (P-16, P-25):** только тайлы с ненулевым счётчиком хождения и тайлы-дороги, по чанкам (маска и массив значений), как разница тайлов. Затухание считается от тика, поэтому хранится значение и тик последнего обновления.
- **Отношения (P-18):** на фракцию список модификаторов (причина, значение, тик создания, затухание). Игрок — тоже фракция, таблица «каждая с каждой».
- **Здания:** уровень, положение, состояние стройки (стадия и тик начала), жильцы и работники. Перенос здания меняет только положение.
- **Поселение и отряд** — отдельные сущности (ADR 0013); отряд хранит состав, еду, добычу, цель.
- **Расы и технологии фракций** — данные (id в сохранении), не копии.
- Миграция v2 → v3 для сохранений без мира уже пустая (старые игры без зданий), поэтому достаточно добавить пустые разделы. Сохранения с миром и старым `WorldGenVersion` не грузятся (ADR 0006).

## Реализация M2: формат v3 (15.10.2026)

- `SaveFormat.CurrentVersion = 3`. В теле добавлен раздел `tiles`, в `components` — хранилища `hero`, `inventory`, `mover` (порядок регистрации: `position`, `revealer`, `hero`, `inventory`, `mover`). Заголовок не менялся. В хэше игры с миром добавлена подсистема `tiles` после `fog`; у симуляции без мира состав и эталоны M0 прежние.
- **Разница тайлов** (`Core.Tiles.TileChanges`): два независимых слоя по чанкам 32×32 — остаток запаса узла (`resources`) и занятость тайла сущностью (`occupancy`). На диске чанк — `x`, `y`, маска из 16 слов `ulong` (бит `ly * 32 + lx`) и значения только для установленных битов в порядке маски; занятость — два параллельных массива `ownerIndices` и `ownerGenerations`. В памяти изменённый чанк плотный (2 КиБ запасов или 8 КиБ владельцев), нетронутый — `null`. Тайл помечается, только когда запас реально уменьшился, поэтому слой каноничен: тот же набор изменений в любом порядке даёт те же байты. Вид ресурса берётся из карты, запас 0 означает, что узла нет. Карта и `MapHash` не меняются.
- **Жилы**: слой умеет уменьшать запас любого тайла, но у героя нет правила добычи для жил, руды и угля (их добывают здания, M3), поэтому суммы `Vein.Stock` генерации не трогаются; остаток жилы — сумма действующих запасов её тайлов.
- **Герой**: характеристики, здоровье, выносливость, занятие, цель добычи, причина последней остановки и итог последнего приказа (имена — snake_case, только дописываются). Инвентарь хранит размеры рюкзака и экипировки и только непустые слоты (`slot`, строковый `item`, `count`): строковые id не сдвигаются при изменении контента. `mover` — цель, дальность остановки, путь (индексы тайлов), индекс и прогресс шага, флаг спринта: после загрузки герой идёт ровно так же, очередь поиска пути сохранять не нужно (поиск синхронный, см. ADR 0003).
- **Миграция v2 → v3** (`SaveMigrationV2ToV3`) добавляет пустые хранилища и пустой `tiles`. Героя она не создаёт (нужны числа из контента): при загрузке мира без компонентов героя `Simulation.Restore` делает героем сущность с `Revealer(Hero)` — данные по умолчанию, пустой инвентарь, стоящий `mover`. Образец `save_v2.sav` проверяется через неё, добавлен образец `save_v3.sav`.
- Эталон `scenario_world_m1` пересчитан (новые хранилища, подсистема `tiles`, приказы героя в сценарии); `replay_basic` и `scenario_m0` не изменились.

## Реализация M2, волна 3: здания в формате v3 (15.10.2026)

- В `components` после `mover` добавлено хранилище `building` (порядок регистрации: `position`, `revealer`, `hero`, `inventory`, `mover`, `building`). Запись: владелец, строковый id типа, уровень, состояние (`constructing`, `active`, `upgrading`, `moving`), оставшиеся тики, левый верхний тайл, поворот, цель переноса (−1 без переноса), поселение. Запас склада — запись в `inventory` с тем же владельцем (`equipmentSize` 0). Занятость тайлов зданием — уже существующий слой `tiles.occupancy`.
- **Формат v3 изменён без новой версии**, потому что v3 ещё не выпущен (ни одного сохранения у игроков нет). Миграция v2 → v3 теперь добавляет и пустой `components.building`; образец `save_v3.sav` пересоздан (костёр построен, дом строится, герой в пути), его ожидания перезаморожены. После выпуска v3 любое такое изменение — только через v4 с миграцией.
- При загрузке здание проверяется по данным (тип, уровень, состояние, тики, поворот, отпечаток в карте, поселение), по занятости (все тайлы отпечатка, при переносе и цели, заняты этим зданием) и по запасу склада (есть ровно у построенного склада, размер — по уровню; при улучшении — по прежнему уровню); центр не больше одного. Ошибка — `InvalidState`.
- Команды `place_building`, `cancel_building`, `upgrade_building`, `move_building`, `demolish_building` записываются в очередь и реплеи (тип здания строкой, сущность — индекс и поколение).
- Эталон `scenario_world_m1` пересчитан ещё раз: изменился только хэш подсистемы `components` (новое пустое хранилище). Добавлен эталон `scenario_m2` (приёмка M2, 735 тиков). `replay_basic` и `scenario_m0` не изменились.

## Реализация M3a, волна 2a: формат v4 (16.10.2026)

- `SaveFormat.CurrentVersion = 4`. В `components` после `building` добавлено хранилище `resident` (порядок регистрации: `position`, `revealer`, `hero`, `inventory`, `mover`, `building`, `resident`), в теле после `tiles` — раздел `settlement = {reachedEra}`. Заголовок не менялся.
- Запись жителя: владелец, имя строкой (из списка `human_names`, чтобы перестановка списка не сдвигала имена), профессия строковым id, 12 навыков массивом (в памяти упакованы по 5 бит в одно `ulong`), дом (индекс и поколение; 0/0 — бездомный), состояние (`arriving`, `idle`, `walking`, `working`, `leaving`), работа (0 — нет; доска задач появится в следующей волне). Позиция и путь жителя лежат в `position` и `mover`, как у героя.
- `settlement.reachedEra` — id наивысшей достигнутой эпохи (пустая строка без мира). Эпоха не падает, когда жителей становится меньше, поэтому здания не оказываются вне территории.
- Поток RNG «события» в коде — `RngStreamId.Events` (бывший `Storyteller`, то же значение 4); имя в сохранении осталось `storyteller`, состав потоков не менялся.
- **Миграция v3 → v4** (`SaveMigrationV3ToV4`): пустое `components.resident` и `settlement.reachedEra = "camp"` для игры с миром (`""` при `mapSize` 0). Образец `save_v3.sav` проверяется через неё; добавлен образец `save_v4.sav` (два жителя, приходящий странник на полпути, отложенная команда `spawn_resident`). Старые образцы не пересоздавались.
- При загрузке житель проверяется: живой владелец с позицией и `mover`, имя есть в списке, профессия существует, навыки 0…20, дом — здание с местами, жильцов в доме не больше мест уровня, работа 0. Ошибка — `InvalidState`.
- Хэш: подсистема `residents` (достигнутая эпоха и хранилище жителей) после `tiles`. Эталоны `scenario_world_m1` и `scenario_m2` пересчитаны: изменились только `components` (новое пустое хранилище) и новая подсистема `residents`; `replay_basic` и `scenario_m0` — только строка `contentHash` (в `economy.json` добавлен `residentStepTicks`). Новый эталон `scenario_m3a_residents`.
- Команда `spawn_resident` (профессия строкой, пустая — следующая по шаблону) пишется в очередь и реплеи.

## Реализация M3a, волна 3: формат v4 дополнен ещё раз (16.10.2026)

- **Формат v4 изменён без новой версии** (не выпущен). В `tiles` после `occupancy` добавлены `flora` и `walks`, оба по чанкам 32×32 (`x`, `y`, маска из 16 `ulong`, значения в порядке маски):
  - `flora` — `states` (`stump`, `sapling`, `tree`), `ticks` (тик срубки, посадки или роста), `stocks` (запас выросшего дерева, 0 у пня и саженца). Проверка при загрузке: тик не в будущем, тайл — суша, не занят зданием, узел карты отсутствует или выработан; у пня и саженца запас 0, у выросшего дерева 1…65535 и только там, где на карте нет дерева (на месте дерева карты отрастает само дерево карты, тайл снова «не изменён»).
  - `walks` — `counters` (счётчик сразу после последнего шага, 1…`maxCounter`), `ticks` (тик шага), `classes` (`none`, `trail`, `road` на тике сохранения). Только тайлы со счётчиком больше 0 на тике сохранения. Проверка: тик не в будущем, класс держится выцветшим счётчиком и не ниже того, что даёт счётчик последнего шага.
- В записи задачи жителя после `nextThinkTick` — `idleLooks` (поиски подряд без работы; 0 при задаче, не больше 30).
- Миграция v3 → v4 дополнена пустыми `tiles.flora` и `tiles.walks` (деревья, срубленные в v3, остаются выработанными: тика срубки нет). Образец `save_v4.sav` пересоздан дважды: с пнями (лесоруб свалил два дерева, третье свалено скриптом), саженцем и счётчиками хождения 41 тайла; затем с `idleLooks` (кузнец без работы после 8 пустых поисков смотрит снова на тике 2412). Остальные замороженные значения не изменились.
- Хэш: подсистема `tiles` пишет после ресурсов и занятости флору и живые тайлы хождения. Эталоны `scenario_m2` и `scenario_world_m1` изменились только в `tiles` (герой ходит теми же путями), затем во всех эталонах — строка `contentHash` (`economy.json`: `storageStacksPerItem`, `idleThinkMaxIntervalTicks`). `scenario_m3a_residents` и `scenario_m3a` пересчитаны: тропы ускоряют жителей (расхождение в `components` с тиков 15 500 / 22 000), затем реже думающие простаивающие жители (с тиков 2500 / 11 500). Новые эталоны бот-симуляции `bot_5.csv`, `bot_12.csv`, `bot_40.csv` и сценарий `bot_scenario.json`.
