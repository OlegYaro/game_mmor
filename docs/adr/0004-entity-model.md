# 0004. Модель сущностей

Статус: предложено
Дата: 2026-10-14
Требования: NFR-02, NFR-04, FR-SAVE-02, FR-SAVE-04

## Контекст

В MVP одновременно живут около 400–500 сущностей: жители, существа, предметы на земле, снаряды. Нужны детерминированный порядок обработки, полная сериализация и простые тесты. Подробности и источники: `docs/research/ecs.md`.

Ключевые выводы исследования:
- Ни одна из восьми проверенных ECS-библиотек для .NET не документирует детерминированный порядок итерации. Автор Arch прямо предлагает сортировать самостоятельно.
- Живые библиотеки: Friflo.Engine.ECS, fennecs, Arch. Заброшены или почти: DefaultEcs, Entitas, Svelto.ECS, Flecs.NET.
- Библиотеки оптимизированы под миллионы сущностей. На 500 сущностях обход массива занимает микросекунды, узкие места будут в поиске пути и ИИ.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Готовая ECS (Friflo, Arch) | Готовые запросы и хранилища | Порядок итерации не гарантирован; чужой формат сериализации; зависимость от чужих релизов |
| Свой тонкий слой: компоненты в массивах + системы | Полный контроль порядка и сериализации; мало кода | Пишем сами около 300–500 строк |
| Классические объекты с наследованием | Привычно | Хуже для сериализации и тестов систем |

## Решение

**Свой тонкий слой сущностей, без внешней ECS-библиотеки.**

- `EntityId` = индекс + поколение. Свободные индексы выдаются из min-кучи, поэтому порядок выдачи детерминирован и переживает сохранение.
- Компоненты — структуры в плотных хранилищах по типу. Обход всегда по возрастанию индекса сущности.
- Структурные изменения внутри тика — через буфер команд, применяется в конце шага системы.
- Фиксированный упорядоченный список систем в `Simulation.Step`.
- Одна точка записи состояния (`StateWriter`) используется и для сохранений, и для хэша (ADR 0005, ADR 0007).
- Определения контента (`Def`) хранятся отдельно и адресуются числовым `DefId` (ADR 0008).

## Последствия

- Обязательные тесты M0: повторное создание сущности даёт тот же индекс с новым поколением; после save/load следующий созданный ID совпадает с непрерывным прогоном.
- Пересмотр, если сущностей станет десятки тысяч или понадобятся иерархии. Тогда первый кандидат — Friflo.Engine.ECS со своим `EntityId` и сортировкой результатов.
