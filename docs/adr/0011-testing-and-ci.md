# 0011. Тестирование и CI

Статус: принято
Дата: 2026-10-14
Требования: NFR-04, NFR-06, NFR-09; правила проекта (Definition of Done)

## Контекст

Логика Core тестируется без редактора. Нужны headless smoke-тест игры, тест-реплей в CI на macOS и Windows, покрытие Core не ниже 70% строк и сборка одной командой. Подробности и источники: `docs/research/testing.md`.

Ключевые факты:
- xUnit v3 работает на .NET 8+. Для порога покрытия через coverlet нужен режим VSTest.
- gdUnit4Net 5.x тестирует C#-код Godot. Тесты по умолчанию идут без рантайма Godot. Godot нужен только для отмеченных тестов и требует переменную `GODOT_BIN`. У проекта есть нестабильность в CI: его собственный CI повторяет тесты из-за случайных падений.
- Необработанное исключение C# в коллбэке Godot не завершает процесс, код выхода остаётся 0. Smoke-тест должен либо искать ошибки в логе, либо игра должна сама выходить с кодом 1.
- Action `chickensoft-games/setup-godot` ставит Godot .NET и шаблоны экспорта на Ubuntu, macOS и Windows.

## Варианты

| Вопрос | Вариант | Плюсы | Минусы |
| --- | --- | --- | --- |
| Тесты Core | xUnit v3 в режиме VSTest | Стандарт; порог покрытия через coverlet работает | — |
| Тесты Core | xUnit v3 на Microsoft Testing Platform | Новее и быстрее | `coverlet.msbuild` с ним не работает |
| Тесты Godot-слоя | gdUnit4Net 5.x | Интеграция с `dotnet test`; поддерживает Godot 4.7.2 | Нестабилен в CI; ввод в headless не работает |
| Тесты Godot-слоя | Chickensoft GoDotTest | Тесты внутри игры, удобно для сцен | Смешивает тесты и игру; в CI нужен виртуальный дисплей |
| Тесты Godot-слоя | Headless smoke-сцена со своим кодом выхода | Ноль зависимостей; проверяет главное: игра стартует и крутит тики | Не заменяет детальные тесты UI |
| Godot в CI | `chickensoft-games/setup-godot` | Ubuntu, macOS, Windows; ставит шаблоны | Сторонний action |
| Godot в CI | `firebelley/godot-export`, Docker-образы `godot-ci` | Готовые сценарии экспорта | Только Ubuntu или не проверены для .NET 4.7 |

## Решение

- **Core.Tests:** xUnit v3 в режиме VSTest, coverlet. Порог 70% строк проверяется ReportGenerator в CI. Имена тестов и атрибут `[Trait("Req", "FR-...")]` ссылаются на ID требований.
- **Виды тестов Core:**
  - юнит-тесты на каждую систему;
  - сценарные тесты на приёмку вех;
  - тест-реплей и save/load (ADR 0005, ADR 0007);
  - архитектурный тест «Core без Godot» (ADR 0002);
  - бенчмарк-тесты с порогами (генерация, тик, поиск пути), отдельная категория, не блокирует быстрый прогон.
- **Smoke-тест игры:** скрипт запускает Godot headless с таймаутом и ограничением по кадрам, пишет лог в файл.
  - В игре стоит глобальный перехватчик: любое необработанное исключение пишется в лог с маркером и завершает процесс с кодом 1.
  - Скрипт дополнительно ищет в логе `ERROR:` и `Unhandled exception`.
  - Специальная smoke-сцена грузит контент, генерирует мир, проходит N тиков и проверяет, что отрисовка получает снимки.
- **Тесты Godot-слоя (gdUnit4Net)** — только когда появится логика в Game, которую нельзя проверить через Core. В M0 не подключаем, чтобы не тянуть нестабильную зависимость раньше времени.
- **CI (GitHub Actions)** — файл готовится в фазе 2, запуск после того, как владелец создаст репозиторий.
  - Задача `core`: матрица из macOS и Windows, сборка, тесты, покрытие, эталонные хэши детерминизма.
  - Задача `smoke`: Ubuntu, Godot headless через setup-godot.
  - Задача `export`: по тегу или вручную, сборки под macOS и Windows.
- **Локально одна команда** для каждого шага: `tools/build`, `tools/test`, `tools/run`, `tools/smoke`, `tools/export`. Скрипты на bash для macOS и PowerShell для Windows.

## Последствия

- Definition of Done: сборка без предупреждений, все тесты зелёные, новая логика покрыта тестами, smoke-тест проходит.
- Не подтверждено и проверяется вручную в фазе 2 на macOS arm64: код выхода при исключении C# в headless-режиме и имя переменной окружения, которую выставляет setup-godot.
