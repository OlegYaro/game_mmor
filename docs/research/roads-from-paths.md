# Дороги из тропинок

Дата: 2026-10-15. Исследование #2 из `docs/MVP.md`, веха M3. Поверхностный проход: глубокая проработка и ADR после «ок» владельца. Решено владельцем (a6): дороги не строятся, а появляются там, где часто ходят. Пометки: **[факт]** есть ссылка; **[оценка]** моя прикидка; **[не подтверждено]** источника не нашёл.

## Краткие выводы

1. Идея «дорогу вытаптывают жители» не новая. Foundation (Polymorph Games) целиком построена на этом: дороги игрок не рисует, их оставляют жители в ходе работы [S1]. Побочный эффект, который отмечают обзоры: жители срезают путь через чужие огороды и обходят запреты [S1]. Нам нужен механизм «запретить вытаптывание» (например, флаг тайла или здание на тайле).
2. Для Cities: Skylines готового мода «тропы по следам» я не нашёл; известно лишь, что пешеходы идут по дорожкам вдвое быстрее, чем по тротуару, и предпочитают их [S2]. Это даёт порядок множителя скорости, но не модель износа. Про износ троп в Farthest Frontier и Going Medieval источников нет **[не подтверждено]**; известно, что в Going Medieval дороги разных материалов ускоряют ходьбу, а предметы на тайле замедляют до 70 % [S3], а в Farthest Frontier ранняя версия давала булыжнику лишь около 10 % выигрыша над грунтом [S4]. Выигрыш 10–40 % считаем нормальным диапазоном.
3. Детерминированная модель: на тайл целое «хождение» `w` (0…255) и тик последнего обновления `t`. Затухание считаем лениво при чтении или записи: `w_eff = max(0, w − (now − t) / D)`, целочисленное деление, `D` из данных. Никаких обходов всей карты каждый тик.
4. Вытаптывание добавляет `+K` при входе существа в тайл. Порядок записи задан порядком обработки сущностей (по ID), поэтому результат одинаков на любой платформе (ADR 0005).
5. Класс тайла (нет / тропа / дорога) выводится из `w_eff` с гистерезисом: подъём при `T_up`, откат при `T_down < T_up`. Иначе картинка будет мигать на границе.
6. Дорога меняет только стоимость тайла в A*, а не связность. Регионы карты связности (ADR 0003) из-за дорог не перестраиваются.
7. В сохранение пишем только тайлы с `w > 0` (с учётом лени: значение и тик) по чанкам 32×32. Пустые чанки не пишем.

## Параметры (стартовые, **[оценка]**, всё в `data/balance/roads.json`)

Игровой день = 15 минут = 9000 тиков. Шаг вытаптывания `K = 4`; затухание `D = 90` тиков на единицу (около 100 единиц в день); `T_up`: тропа 40, дорога 120; `T_down`: 25 и 90; потолок 255. Тайл, по которому проходит около 30 раз в день, стабильно держит тропу; около 70 в день, дорогу. Множители стоимости тайла в A*: тропа 80 % (8 вместо 10), дорога 60 % (6). Дорога по склону и в воде не образуется (непроходимое и вода исключены).

Связь с A*: при множителе меньше 100 % эвристика с шагом 10 перестаёт быть допустимой. Нужно либо брать для эвристики минимальную стоимость шага из данных (6), либо считать неоптимальный путь приемлемым (RimWorld так и делает, взвешивая эвристику) [S5]. Агенту, который уже идёт, перепланирование из-за смены класса тайла не нужно: путь остаётся валидным, лишь неидеальным.

## Варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| A. Плотный массив `ushort w` + `uint t` на тайл | Просто, быстро | 2048² × 6 Б ≈ 25 МБ, из них почти всё нули; сохранение приходится фильтровать |
| B. Разреженные чанки 32×32: выделяются при первом шаге | Память пропорциональна вытоптанному; естественная единица сохранения (мир уже режется на чанки) | Чуть больше кода; нужна очистка «остывших» чанков |
| C. Глобальное затухание обходом раз в N тиков | Не нужно хранить `t` | Спайки времени; затухание ступенчатое; обход миллионов тайлов |
| D. Только шаги героя и жителей в активной зоне | Дёшево | Дороги не растут на стратегическом слое (приемлемо для MVP, нужно для караванов v1) |

## Производительность на 2048²

Пишем только при смене тайла сущностью (около 100 жителей, примерно 1–3 входа в тайл в секунду на каждого) — порядка сотен записей в секунду, это дёшево **[оценка]**. Чтение стоимости для A* — один индекс чанка и обращение к ячейке; пустой чанк (`null`) даёт базовую стоимость без вычислений. Класс тайла для отрисовки: очередь «тайл сменит класс не раньше тика X», упорядоченная по тику, а не обход карты. Бенчмарк с лимитом по времени помечаем `Category=Benchmark`, как остальные (см. CI).

## Рекомендация

Вариант B с ленивым затуханием, целыми числами и гистерезисом; в MVP вытаптывание только в активной зоне (D), караваны на дорогах отложить до v1 (ROADMAP: «дороги ускоряют переход»). Числа держим в данных. Нужно ещё обсудить с владельцем: можно ли запрещать тропы (огороды, поля) и показывать ли `w` в инспекторе; это не решено.

## Когда понадобится

M3 (жители и перемещение по задачам). Тесты на детерминизм (реплей) и на сохранение (запись и чтение даёт тот же хэш) нужны сразу. Для A* меняем только функцию стоимости тайла, ADR 0003 не пересматривается.
