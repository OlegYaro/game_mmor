# План качества перед публичным релизом

Составлен 16.10.2026. Цель: игра выходит не для себя, а для общего пользования, поэтому дефекты нужно находить до игроков. Абсолютно «ни единого изъяна» не гарантирует никто; этот документ описывает слои проверок, критерии «можно выпускать» и то, что нельзя заменить автоматикой. Источники требований: NFR-01…09 в `docs/GDD.md`, `docs/requirements-index.md`, ADR 0005, 0007, 0011.

## 2. Слои проверок и когда их добавлять

Писать тесты для систем, которых ещё нет, не имеет смысла; слои добавляются вместе с системами.

| Слой | Что даёт | Когда |
| --- | --- | --- |
| Windows CI зелёный | игра работает на второй платформе MVP (P-04) | **сейчас**, до релиза; нужен лог шага «Test with coverage» job `core (windows-latest)` или токен `GH_TOKEN` |
| Бот-симуляция на 100+ игровых дней | находит экономические тупики, застрявших жителей, невозможные состояния; метрики по дням | M3 (экономика), расширять в M4–M5 |
| Fuzz и случайные сценарии: тысячи seed, случайные допустимые команды | падения, расхождения детерминизма, нарушения инвариантов | M3, затем по мере новых систем |
| Автотест интерфейса в Godot (клики, скриншоты) | поломки отображения и ввода | после M2 |
| Живая игра: владелец и знакомые | баланс, понятность, «интересно ли» — автоматика этого не видит | с M2, постоянно |
| Нагрузочные проверки | NFR-01 (60 FPS, 100 жителей, 300 существ), NFR-02 (тик ≤ 8 мс), NFR-03 (память ≤ 2 ГБ), осада 100+ бойцов | M4–M5 |
| Закрытая бета: 20–50 внешних игроков, сбор логов | реальное железо и поведение игроков | перед v1 |
| Проверка лицензий и зависимостей: пакеты NuGet, шрифты, арт, звук, FastNoiseLite (MIT) | юридическая чистота публичной игры | перед релизом |
| Аудит безопасности: чтение сохранений и модов из файлов | защита от повреждённых и вредоносных файлов | перед релизом (моды — v2) |

## 3. Критерии «можно выпускать» (чек-лист релиза)

Всё ниже должно быть истинным; пункты с отметкой «человек» автоматикой не закрываются.

1. Сборка без предупреждений, все тесты зелёные на **macOS и Windows** (CI), покрытие Core не ниже 70%.
2. Нет известных падений и потери сохранений. Сохранения всех предыдущих версий релиза загружаются (образцы в `tests/Core.Tests/Golden`).
3. Реплеи детерминированы на обеих платформах (эталонные хэши совпадают на macOS и Windows).
4. Бот-симуляция 100 игровых дней на нескольких seed проходит без тупиков; fuzz без падений.
5. Производительность: NFR-01…03 выполнены на слабом тестовом железе (человек: нужны машины слабее разработческой).
6. Игра полностью проходима от старта до конца цикла MVP (поселение → набег → уничтожение лагеря) (человек).
7. Тест на нескольких машинах и разрешениях, русская и английская локализации, нет обрезанного текста (человек).
8. Отчёт о падениях: `CrashGuard` пишет лог, игрок может его приложить; приватные данные в логах отсутствуют.
9. Список известных проблем в README честно описывает, что не работает.
10. Контент заморожен перед релизом: дальше только исправления. Версия игры, версия формата сохранений и версия генератора мира зафиксированы.
11. Закрытая бета пройдена, критичные замечания закрыты (человек).
12. Лицензии проверены, в игру не попали материалы без прав.

## 4. Процесс

- После каждой вехи: полный прогон (тесты с покрытием, бенчмарки, smoke, схемы), запись в `docs/PROGRESS.md`.
- Любое изменение `data/` или генератора меняет `contentHash` и эталоны: пересоздаются осознанно, diff смотрится глазами.
- Каждая найденная ошибка получает тест, который её воспроизводит, до исправления.
- Перед публичным релизом: сначала закрытая бета, потом релиз-кандидат с заморозкой контента, потом публикация.
- После релиза: правило совместимости. Старая версия генератора мира должна воспроизводиться или сохранение должно мигрировать (открыто, `docs/open-questions.md` E12).

## 5. Ограничения (что делает только человек)

- Ручная игра в Godot: вид, ощущение управления, читаемость интерфейса, интерес.
- Проверка на других компьютерах и операционных системах (у разработки только macOS).
- Набор и общение с тестировщиками, юридические вопросы.
