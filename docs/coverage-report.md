# Отчёт о покрытии кода (16.10.2026, после M2)

Снимок: полный прогон всех 1028 тестов в Release с покрытием (`COVERAGE=1 CONFIGURATION=Release tools/test.sh`, настройки `tests/Core.Tests/coverage.runsettings`: только сборка Core, SingleHit). Сырой отчёт и HTML лежат в `TestResults/` (не в git); воспроизвести: команда выше, затем `dotnet reportgenerator -reports:"TestResults/**/coverage.cobertura.xml" -targetdir:TestResults/report -reporttypes:Html`.

## Выводы

1. **Проверка порога считает 84,4%** (порог 70%, NFR-06), ветки 72,7%.
2. **Наш собственный код покрыт на 98,5%**: из 6021 строки без покрытия только 92. Остальное, что занижает цифру, — не наш код:
   - сгенерированные файлы `System.Text.Json` source generator (`obj/.../*.g.cs`, 15 749 строк, ветки обработки ошибок и необязательных членов, которые никакой тест не должен вызывать);
   - `WorldGen/Noise/FastNoiseLite.cs`: сторонняя библиотека (MIT), используется только OpenSimplex2 и его окрестности, остальные типы шума не нужны (покрыто 26%).
3. **Тяжёлые и медленные тесты** (бенчмарки, большие карты) в этом прогоне выполнены и дополнительного покрытия не дали: цифра та же, что без них.
4. Одно ожидаемое «падение» под покрытием: `PathfindingBenchmarkTests.HundredWalkersOn512StayInsideTheTickBudget(goalRadius: 0)`: тик 6,97 мс при лимите 4 мс. Бенчмарки со временем измеряются в Release **без** покрытия (в CI это job `benchmarks`); в Debug они тоже превышают лимиты. Это не дефект логики.
5. Стабильность: полный обычный набор 3 раза подряд в Release (1004 теста), падений нет; Debug полный: 2 ожидаемых падения тех же бенчмарков.
